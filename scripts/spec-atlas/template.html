Merely Spec Atlas

Every repo in the merely-made family checked against the specs it implements, depends on, or ought to follow. Genet is also measured against the whole web platform: __NCAT__ browser specs joined to its WPT census, IDL and CSS property coverage.

Is every app built on a spec? Yes, with three qualifications.

  • Every repo has at least one relevant spec, and for about half the family a spec is the product itself: genet, netfetcher, vano, bole, smolweb, turquet, wavicle and emblem. Specs don't reach the house-grammar crates: scenograph, chirograph, platen, servitor, armillary and the UI internals. Those formats are Merely's own and ought to be published as specs.
  • “W3C” is too narrow a word for it. The core of the web engine is WHATWG (HTML, DOM, Fetch, URL, Encoding, Streams): about three-quarters of genet's passing WPT subtests (24,756 of 33,824 in the 2026-09-29 census). Outside the browser, most of what the apps implement is IETF RFCs or community specs (Gemini, Reticulum, LXMF, Meshtastic, Djot, WavPack, IconVG), plus IAU/IERS for the sky.
  • W3C's distinctive share is data, identity and annotation. mere already ships JSON-LD, RDF 1.2, SPARQL 1.2, Web Annotation and DTCG tokens, and dramatis speaks did:key. The unused fits are a short list: RDFC-1.0, SHACL, VC 2.0, PROV-O as a model, ActivityPub, WebSub, Webmention, PLS, MusicXML and WCAG statements.

§6

Where the leverage is

Strong fits nobody has adopted

  • RDFC-1.0 + Data Integrity for mere-linked-data. It already promises byte-stable normalized datasets; canonicalization would make graph exports signable with insigne keys.
  • SHACL as the ingest validator, replacing eidetic's own JSON-schema codicils and the open-IRI “recognized core”.
  • PROV-O as a model, not seven constants. It fits mere statements, cleromancy's reading receipts and isocosm's chronicles.
  • VC 2.0 / DID Core for insigne delegation certificates, which are already VC-shaped. gaz already parses did:key and did:plc.
  • WebSub, Webmention, ActivityPub for turnstone feeds and peer places. WARC (ISO 28500) for page capture.
  • PLS (W3C Rec) as mora's lexicon format; MusicXML/MNX and Standard MIDI Files for woodshed.
  • Web Serial, WebUSB, Web Bluetooth for a browser-hosted Signalman and Linkboy.

Conformance suites that exist but aren't wired

  • WPT fetch/ against netfetcher directly. It claims Fetch, CORS, SRI and Referrer Policy, but has no suite run of its own.
  • Official Lua 5.4 tests for didgeridoo; today it has a hand-kept matrix of roughly 62 implemented functions to 80 unimplemented.
  • test262 intl402 and Annex B: skipped in vano and bole runs, so ES coverage is understated and Intl unmeasured.
  • WebGL CTS for netrender's WebGL2 route, and a CSS reftest census for genet newer than the 2026-08-24 map (that map is on o-pc).
  • Djot reference tests for knot and nematic; the Web Annotation test suite for fleece and woodshed's Redshank export.
  • Spec-derived vectors for retinue, outrider, sennet and tucket, which today qualify only against pinned reference peers.

From atlas to registry

Genet's standards-to-features ledger admits a row only when a consumer asks: “A feature nobody has asked for is not a row.” mere has its own 174-verdict standards survey and a W3C architecture review. If the stack's purpose is implementing specs, the inverse ledger is a family-wide registry: every relevant spec as a row, with owner repo, depth and the suite that measures it, and the consumers filling in a “why now” column. That registry now exists: content/specs.toml in merelyllc.com, with its plan in docs/2026-10-18_family_spec_registry_plan.md.

§7

Method and limits

  • Catalogs: browser-specs@4 (615 specs with WPT paths), W3C API /specifications (1,720 TR docs), @webref/css 8.7.7 (758 properties). Fetched 2026-10-18.
  • Genet measures: WPT outcomes from design_docs/receipts/2026-09-29_vano_wpt_census, joined to each spec's testPaths. Overlapping paths can count toward more than one spec. IDL and CSS coverage are name-mention heuristics over genet components/ at 6f00922. They show footprint, not conformance: shorthands and generated names can be missed, and common words like Range can over-count.
  • Repo maps: read-only surveys of READMEs, manifests, design docs and source greps across 25 repos: the 23 code repos in merely-made, plus hocket and netfetcher. Nothing was built or run. Depth reflects each repo's own receipts and docs.
  • Local repos/retinue is the murm repository (same origin). mere's tables reflect main as of today.
